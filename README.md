# Kraft

A fictional, curation-first music service, built as an educational demo of how a
design file in **Paper**, a static **JSON API**, an **AI artwork pipeline** and a
**React app** stay connected through Paper's MCP server.

Everything in it is invented: the artists, the records, the curators, the cities
people listen from. The point is not the product. The point is that one set of
tokens, one catalogue and one art direction drive a design canvas and a running
app at the same time, and that anyone can rebuild the whole thing from this repo.

This repo is the **source of truth**. The Paper file follows it, never the other
way round. When the project is simplified or extended, it happens here first.

## Replicate this

You need Node 20+, pnpm 9+, a Paper account, and an MCP client connected to
Paper (Claude Code was used here; any client that can call Paper's tools works).

**1. Run it.**

```bash
git clone <this repo> kraft && cd kraft
pnpm install
pnpm build        # data/ → api/, then the app → app/dist
pnpm dev          # app on http://localhost:5173, homepage at /welcome
pnpm validate     # the rules in CANON.md, as a report
```

**2. Get the Paper side.** Either duplicate the Paper file linked above, or
rebuild it from `paper/`, in this order:

1. **Tokens.** `paper/tokens.json` is the exact output of `get_tokens`. Feed it
   to `create_tokens` in a fresh file; the app's `app/src/styles/tokens.css` is
   the same set split onto two axes (theme primitives, mode roles).
2. **Components.** `paper/components/*.jsx` is `get_jsx` of every entry on the
   *Components* artboard, inline styles bound to the tokens. Paste an entry into
   `write_html` to recreate it; `paper/screens/02-components.png` shows the
   whole artboard for reference.
3. **Screens.** `paper/screens/` has every desktop artboard, dark and light, plus
   the marketing pages. They are the targets; the app is the implementation.
4. **Artwork.** `paper/prompts/` holds the prompt sets the canvas artwork was
   generated from, as ready-to-use `paper-gen://` URLs. See *Artwork* below
   before spending generation credit.

**3. Change the world.** Edit `data/*.json`, run `pnpm validate`, then
`pnpm build`. The app reads `api/` as static files, so every change is visible
on the next reload, and the strings the canvas shows (`metaLine`, `duration`,
`followersLabel`) are the ones the build computes.

**4. Deploy.** `vercel.json` at the root does it: install with pnpm, run
`pnpm build`, serve `app/dist`, and rewrite every app route to `index.html`
while `api/`, `artwork/` and `globe/` stay static. Import the repo in Vercel and
keep the defaults.

## Layout

```
data/       hand-authored canon — the source of truth
api/        generated by scripts/build.mjs; committed so endpoints are browsable
schema/     TypeScript shapes for every endpoint
scripts/    build, validate, artwork prompts, country cards, name check, serve
public/     generated artwork (JPEG covers, PNG country cards)
paper/      exports from the Paper file: tokens, component JSX, screens, prompts
app/        the Vite + React app (a pnpm workspace package, @kraft/app)
CANON.md    the rules; PLAN.md the dated history of every decision
```

`data/` is what you edit. `api/` and `app/public/{api,artwork}` are build artefacts.

## Commands

```bash
pnpm build            # api + app
pnpm build:api        # data/ → api/ only
pnpm validate         # integrity, realism, legal, geography, design-drift report
pnpm dev              # app dev server
pnpm serve            # api/ over HTTP on :4173, for Paper or another client
pnpm artwork -- --kind album --limit 10     # paper-gen:// prompts for covers
pnpm countries -- --missing --format card   # country cards as Paper HTML
pnpm check-names -- --authored              # live MusicBrainz negative check
```

## Why a static API and not a service

The demo has to survive being live, public and editable. A folder of JSON files
beats a running service on every axis that matters here: no keys, no rate
limits, nothing to fall over while someone is watching; deterministic strings,
so a card designed around a title never meets a longer one by surprise; safe
public editing; and legibility. Open `api/` and you can see exactly what the
product "knows".

## Endpoints

| Path | What |
|---|---|
| `/` | manifest, canon constants, disclaimer, counts |
| `/home` | Home feed: lists updated by people you follow, each with its note; continue; who is on; Around the world; three scenes |
| `/explore` | Curators, scenes, browse tiles |
| `/library` | Lists · Albums · Artists, plus what you follow |
| `/search` | placeholder and recent searches |
| `/player` | now playing, position, queue with next-up |
| `/activity` | this week: list updates, replies pinned to a second, reposts, follows |
| `/globe` | listening now: geolocated points for the homepage globe |
| `/countries` | the country cards and their lists |
| `/genres`, `/scenes` | taxonomy and moods; a scene is a label, a city and a look |
| `/curators/{slug}`, `/labels` | a curator's profile, lists and notes; the imprints |
| `/artists/{slug}` | bio, discography, popular tracks, who shelved them, artwork briefs |
| `/albums/{slug}` | tracklist, label, artwork brief |
| `/playlists/{slug}` | description, curator, tracklist, `metaLine` |
| `/tracks/index` | every track |

Every entity carries **both** the raw value and the display string: developers
bind to `durationSec` / `playCount`, designers paste `duration` ("4:12") /
`playCountLabel` ("3,214,880") / `metaLine` ("10 tracks · 46 min"). The strings
are built to match the artboards exactly.

## Artwork

Covers are generated inside Paper from prompts this repo writes. `pnpm artwork`
emits `paper-gen://` URLs; each image spends generation usage, and a single
`write_html` call may carry at most **10** images, so `--limit` defaults to 10.
Covers generate **without text** by default, because models garble type.

Art direction lives in `scripts/lib/artwork.mjs` on two axes: **genre voice**
supplies palette and subject, **release year** supplies medium and composition.
A 1962 jazz record and a 2024 jazz record share a palette and nothing else. All
of it stays off the app's plum and slate chrome (CANON §Artwork).

The finished renders are exported from Paper at 1024px into `public/artwork/`
and keyed in `data/artwork.json`; `data/artwork-paper.json` keeps the Paper CDN
URL of the same render so the canvas and the app read one source. Forty-five
keys are filled today; `pnpm artwork -- --missing` lists the rest.

### Country cards

A typographic template on the canvas (`Country / <name> · <city>`) over a
16-bit pixel-art strip of one city. `data/countries.json` holds one entry per
country: ISO code, the gazetteer city, landmarks left to right, a palette named
after real things there. The prompt is STYLE + TONE + LAYOUT (constant, in
`scripts/lib/place-art.mjs`) + PLACE. `--snap` crops a render to the 108×59
grid, clusters it to 16 colours and writes `public/artwork/country/<slug>.png`.
A card with a `list` also becomes a list (`pl_country-<slug>`) whose cover is
the card exported at 640px. Six cards still have no art; `pnpm countries --
--missing` lists them.

## Geography

`data/places.json` is the one gazetteer: every curator, scene and artist carries
a `placeId`, resolved by the build to `geo: { placeId, city, country, lat, lng }`.
`data/listening.json` is *who is playing what, where, right now*: nine curators
at home on the list they are playing, plus anonymous members. The build emits
`api/globe.json`: `listeningNow` (2% of monthly actives), `points[]` and
`places[]`. The homepage globe (`app/src/components/Globe.jsx`, globe.gl) reads
only that file.

## The app

`app/` is a Vite + React SPA. Before `dev` and `build`, `app/scripts/sync-data.mjs`
copies `api/` and `public/artwork/` into `app/public/` so Vite serves them as
plain files.

- `src/styles/tokens.css` is Paper's token set split on two axes: primitives
  under `[data-theme="plum" | "graphite"]`, roles under `[data-mode="dark" |
  "light"]`. Components read only the roles. Settings switches both axes,
  with a *System* mode that follows the OS.
- One component per Components-artboard entry, values taken with `get_jsx` and
  `get_computed_styles`, never from screenshots.
- Routes: `/`, `/explore`, `/library`, `/lists/:slug`, `/curators/:slug`,
  `/artists/:slug`, `/now-playing`, `/countries`, `/settings`, and `/welcome`,
  the logged-out homepage with the globe, outside the app shell.
- Playback is fake but live; follow state lives in `localStorage`.

## Legal posture

Everything is invented. `data/real-world-blocklist.json` plus a live MusicBrainz
negative check keep it that way: MusicBrainz core data is CC0 and nothing from
it enters the product, it is only ever asked whether an invented name is taken.
Four artist names that collided with real acts were renamed on 2026-09-15
(CANON §Legal). The product name itself, Kraft, is a known collision, kept on
the record as a decision. The disclaimer in `api/index.json` ships in the
footer.

**Third-party assets.** Inter and Instrument Sans load from Google Fonts (SIL
Open Font License). `app/public/globe/earth-night.jpg` is the night-lights
texture from the three-globe examples, derived from NASA Visible Earth imagery
(public domain). globe.gl is MIT.
